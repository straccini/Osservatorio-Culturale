L1 · Design del Knowledge Layer

Decisioni: entità Persone · Strutture · Temi · Progetti · estrazione integrata nello scanner + backfill · opinion leader dai contenuti ora (persona-centriche in L3/L4) · nomi uniti con chiave normalizzata + alias + merge admin.

Il flusso (additivo: non stravolge gli scanner)
1. Scanner
estrae il contenuto
(come oggi)
→
2. Stessa chiamata Claude
estrae anche le entità
persone, strutture, temi, progetti
→
3. Normalizza
chiave + alias
"ICOM" = "ICOM Italia"
→
4. Scrive
upsert Entita + append Occorrenza (con data)
+ Backfill una-tantum → ripassa lo storico (AgentScanResults, Items, Bandi_v5) per popolare subito Entita/Occorrenze.
Foglio · Entita (una riga per entità unica)
id · nome_canonico · tipo (persona/struttura/tema/progetto)
alias[] · ambiti (1-5) · n_occorrenze
prima_data · ultima_data · n_fonti
score_autorevolezza · stato (auto/confermato/unito)
Foglio · Occorrenze (una riga per menzione)
id · entita_id → Entita
contenuto_id · tipo_contenuto (bando/news/norma/podcast/video)
data · ambito · fonte
È la serie storica: da qui nascono trend (L2) e autorevolezza (L3).

Dentro L1 (ora)

  • Estrazione entità integrata + backfill storico
  • Normalizzazione + alias + merge admin
  • Accumulo con date (Occorrenze) + conteggi base + score autorevolezza semplice
  • Vista admin minima "Entità" (top per occorrenze/recenza) per vederlo funzionare

Fuori (rimandato)

  • Algoritmi di trend / momentum → L2
  • Ranking + grafo relazioni opinion leader → L3
  • Fonti persona-centriche / social wall → L3/L4
